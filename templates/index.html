Topics / Forum mode -

Required before app-data backup can store anything - this is a real, visible change to your archive group in any Telegram client, not just an internal app setting. Poggram keeps it on once enabled, because backups currently have nowhere else to live; that restriction lifts if backups can be exported elsewhere.

Back up app data

Keeps your folder structure and file index backed up in a dedicated "App Data" topic in your archive group, so switching machines or losing your local index isn't a disaster. Backs up once when you close the app, and only if something actually changed since the last backup. Use "Back up now" below any time you want one immediately. Never includes your Telegram session, API credentials, or phone number, under any circumstances.

Include thumbnails

Off by default, and usually best left off - thumbnails are nearly the entire size and time cost of a backup, and they're the one part that doesn't need backing up: any missing thumbnail is rebuilt on demand from Telegram's own copy, or regenerated from the video itself, and cached again as you browse. Turn this on only if you want a restored machine to look complete instantly, including offline.

Check for newer backup on startup

Useful if you switch between machines - only ever notifies and asks before restoring anything, never restores automatically.

Local cache-

Cached file chunks are just a local speed optimization for repeat streaming/downloads. Clearing it frees disk space immediately, and your files stay safely in Telegram - they're simply re-fetched next time they're opened.

Upload & download

Two different things, easy to mix up: Files at once = how many separate files move together. Streams = how many pieces of one file move together. They multiply, so 3 files x 8 streams = 24 requests at once.

Max file chunk size MB

Files larger than this get split across multiple Telegram messages automatically - lower this to test the splitting logic without a genuinely huge file.

Files at once files (1-10)

How many whole files transfer at the same time, for both manual transfers and background sync. Higher speeds up bulk operations but raises flood-wait risk. Default 3.

Download streams streams (1-16)

How many pieces of a single file download in parallel. Higher is faster, but raises the chance one stalled piece holds up the rest. Default 8.

Upload streams streams (1-16)

How many pieces of a single file upload in parallel. 1 = fully sequential. Default 8.

Completed uploads

Whether completed uploads stay visible in the Transfers tab after a restart. "Clear on restart" matches the historical behavior; "Keep until dismissed" persists them until you manually clear or dismiss them.

Upload part size KB (0 = auto)

How big each upload piece is. 0 (default) picks automatically by file size, which is almost always what you want.

Max upload request size GB (0 = no limit)

Safety ceiling on a single upload request. Only applies when the browser sends the file itself - the file picker, "upload new version", and drag-and-drop. Dragging from Explorer or using the folder picker passes a path instead and is never limited. 64 GB default; raise it only if you hit it.

Sync backoff during activity streams

Upload streams a background sync keeps while you're actively using the app. 1 (default) yields hardest, so your own transfers stay responsive. Raise it toward "Upload streams" above for more sync throughput instead.

Thumbnails

All three apply only to thumbnails generated after you save - never to anything already cached, and never to the small thumb stored alongside the file in Telegram.

Thumbnail format

Format for newly-generated local thumbnails (new uploads, "use this frame as thumbnail", cache regeneration). JPEG (default) is the safe, well-tested choice. AVIF cuts thumbnail cache/backup size roughly in half at the same quality setting, but can look softer at small thumbnail sizes - only changes thumbnails generated after saving this, not anything already cached.

Thumbnail quality

Encoder quality (1-100) for newly-generated local thumbnails only - never the Telegram-stored document thumb, which always uses a fixed safe quality regardless of this. Higher = larger files, less compression artifacting.

Chroma subsampling

Controls color compression for newly-generated local thumbnails. Lower = less color information, smaller file size. Default matches the encoder's own choice. 4:4:4 = full color, highest quality/size. 4:2:2 = less color (small visual difference), significant space-saving. 4:2:0 = colors may appear washed out.

Video player
External video player

Adds a "Play in video player" option, in the video viewer and the right-click menu, that launches an external program instead. "Open" always uses the in-app player either way - this is only for when you want a dedicated program's own codec/subtitle support instead. Off by default.

Video player path

Only used when "External video player" above is enabled. Auto-detected if MPC-HC is installed in a common location; override here if not, or to use a different player.

Interface
Transfers tab position

Choose where the Transfers/Sync/Settings group sits in the sidebar.

Item size 160px

How large files and folders are in Explorer, in both grid and list view. The S/M/L buttons above each view are shortcuts to three of these steps - drag for the sizes in between. Below 100px only grid cards keep shrinking; list rows stay at their 100px density.

Close to tray

Closing the window parks Poggram in the system tray instead of quitting, so transfers and folder sync keep running. Use the tray icon's Quit to exit properly. Turn this off to make the window's X quit as usual.

Log

Everything the app logs is written to data/poggram.log, so you don't need the console window open to see what happened. To start Poggram without a console at all, launch it with pythonw.exe (or the included Poggram.vbs) instead of python.exe.
